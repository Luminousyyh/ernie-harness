05 / DAILY WORK

Start with a concrete goal.

Run tasks in your project directory. -w selects a directory; otherwise new CLI goals use the selected workspace. Supervised goals require an acceptance command.

pnpm cli workspace add "D:/projects/my-app" --name "my-app"
pnpm cli workspace list
pnpm cli run "Fix the empty-array case and add a regression test" -w "D:/projects/my-app" -c "pnpm test" --supervised
pnpm cli list
pnpm cli show <goal-id>
pnpm cli pause <goal-id>
pnpm cli resume <goal-id>

pnpm cli tui -w "D:/projects/my-app" opens the terminal UI; pnpm cli open opens the local Web workspace. Select a workspace, start a chat, and inspect tool and acceptance records. Use pnpm cli reply <goal-id> "Add error handling" to continue; cumulative budgets persist.

Background goals can continue when the page closes; service exit pauses work. Reconcile uncertain writes against the actual workspace and tool journal before resuming.

06 / SHARED EXECUTION

One execution core.

CLI, terminal, and the Chinese / English application UI share persistent state through the service. Contracts describe data; execution, provider, and storage modules implement it. The browser uses HTTP / SSE and receives no model credentials.

  1. CLI / Web
  2. HTTP / SSE
  3. Engine + Supervisor
  4. Tools + OpenRouter
  5. SQLite journal

Execution and recovery

Persist write intent before execution and record the result afterward. Reconcile uncertain effects before recovery. Allow one writer per workspace.

Budgets and model policy

Only baidu/ernie-5.5-flash-preview:free is allowed. Auxiliary, reflection, retry, and improvement calls must share cumulative budgets. Quota exhaustion preserves state.

Local shell execution is trusted. File boundary checks do not sandbox arbitrary code running as the same user. Formal remote evaluation has a separate Linux / Bubblewrap protocol.

07 / LEARNING & IMPROVEMENT

Make experience inspectable.

Learning and improvement mechanisms are being integrated. This describes their mechanisms and acceptance boundaries. Live model benefit is unverified; no maturity or unconditional self-improvement claim is made.

Research inspirationApplication mechanismEvidence boundary
ACEExtract experience candidates from attributed trajectories; retrieve by scope, merge, deduplicate, and separate candidates from promoted entries.Integration verification pending; requires offline behavior checks and independent live tasks.
ReflexionPersist verbal reflections with failure evidence for later attempts. A reflection offers advice and does not establish test success.Reflection calls count toward budgets; model self-assessment cannot establish promotion.
Meta / MESHSeparate task execution from improvement runs; record candidates, revisions, evaluations, and reversible promotion decisions.Mechanism inspiration, without claiming to reproduce the published systems.
SICA / HyperagentsTurn improvement proposals into candidate patches in isolated worktrees; verify before considering promotion under the current policy.Inspect implementation and gates; protected paths, hidden tests, and required review cannot be bypassed.

Attributed failure → candidate experience or patch → isolated validation → independent acceptance → promotion or retained candidate. Offline feature tests do not establish learning benefit, generalization, or a performance advantage.

08 / EXTEND THE HARNESS

Start with a bounded tool.

The current extension path is through source changes, without a claimed dynamic plugin marketplace. For a read-only project_summary tool, define its input and result contract, check directory boundaries, register its schema, and test success and traversal rejection.

  1. Define shared types in src/contracts; contracts must not import implementations.
  2. Implement and register the tool in src/tools; keep credentials and uncontrolled file contents out of logs.
  3. For persistent effects, journal intent and result and define reconciliation for interrupted, uncertain outcomes.
  4. Add behavior tests, run typecheck, test, and build, then perform separately authorized live model validation.

Learning providers and improvement candidates must obey cumulative budgets, workspace write ownership, and evidence provenance. The actual source and its tests define available interfaces.

A FEW MORE THINGS

Before you start.

Is this an official Baidu product?＋

ERNIE Harness is an independent research and development project, unaffiliated with and not endorsed by Baidu, DeepSeek, Pi, or Anthropic. Names and trademarks belong to their owners.

What do I need?＋

Use Node.js 24.9 or later, pnpm 10.30.3, and OpenRouter credentials for the designated free ERNIE route. Web and CLI share configuration. Remote sandbox evaluation requires Linux and Bubblewrap.

Does this website call a model?＋

This static site uses illustrative data. It does not accept API keys, connect to models, or execute project code. Run the actual workspace locally using the setup guide.

Does a free model mean unlimited usage?＋

The free route is subject to account limits, provider quota, and availability. Requests and retries count cumulatively; quota exhaustion preserves state without switching to a paid model.

How can I contribute?＋

Open an issue, improve documentation, or propose a pull request on GitHub. Original code is MIT licensed; reference materials keep their upstream licenses. MIT does not grant trademark rights.
