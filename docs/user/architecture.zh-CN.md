# 架构与模块所有权

[English](architecture.md) · [使用指南](guide.zh-CN.md)

ERNIE Harness 是独立实现的 TypeScript Harness。默认每个工作区一个写入者；契约不能导入实现；浏览器通过 HTTP/SSE 通信，不处理模型凭据。

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| `src/contracts` | 目标、工具、事件、证据类型 | 纯契约，不依赖实现 |
| `src/provider` | OpenRouter、路由、凭据、额度、用量 | 仅指定免费 ERNIE，凭据仅在运行时 |
| `src/tools` | 文件、搜索、修改、进程与差异 | 路径约束、输出限额、脱敏；本地 Shell 仍是可信执行 |
| `src/core` | 模型/工具轮次、上下文、计划与完成 | 终止状态前检查证据和预算 |
| `src/store` | SQLite 状态与事件 | 副作用前保存意图，保留不确定结果 |
| `src/supervisor` | 持久调度、依赖、隔离工作树 | 共享预算、每个工作区一个写入者 |
| `src/server`、`src/cli`、`web` | 服务、终端、界面 | HTTP/SSE 状态投影；不向 UI 提供模型密钥 |
| `src/learning` | 分区经验、证据链接、辅助尝试 | 正在集成；经验属于不可信建议 |
| `src/extensions` | 技能上下文、MCP、可信插件契约 | 显式配置、输出带来源；插件不是沙箱 |
| `src/improvement` | 候选、隔离验证、评估与归档 | 候选特定验收、保护检查与可回滚决策 |
| `src/runtime` | 正在集成的权限与检查点策略 | 存在策略类型不等于通过行为门槛 |

## 一次任务轮次

1. 载入目标版本、工作区、工具、权限与累计预算。
2. 构建带来源的上下文，分开呈现请求估算与真实用量。
3. 提供商请求前预留预算，响应后保存真实输出与用量。
4. 修改工作区前记录工具意图，执行后保存成功、失败或不确定结果。
5. 监督目标只有当前版本、当前工作区的独立验收通过后才能完成。

重启时必须核对有意图却无法确定结果的工具操作。未经检查就重放中断的写入可能破坏状态。暂停停止新调度并保留日志；验收不能来自反思、模型自行填写的检查点或其他版本的历史结果。

## 围绕内核的改进

学习、扩展与改进模块正在并行集成，不能改变固定模型、工作区所有权、凭据和日志边界。目标流程为观察 → 候选 → 有边界的验证 → 显式决策。参见实际源码与[机制对照](../research/harness-learning.md)；本文不宣称跨任务收益或真实模型验证已完成。

## 部署与证据

本地应用面向可信用户，不是多租户代码沙箱。正式评测有独立远程 Linux/Bubblewrap 与 broker 边界。静态网站与两者分离：仅 HTML/CSS/JS，不访问模型、不收集凭据、不追踪访客。浏览器测试验证展示行为，不验证代理能力。
